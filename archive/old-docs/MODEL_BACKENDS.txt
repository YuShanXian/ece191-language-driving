Historical language-provider interface

The menu affects new language requests, not map selection or trajectory
construction. Requests are serialized. Only enabled identifiers in the model
catalog are accepted. Provider failure preserves vehicle state and reports an
error rather than silently selecting a different provider.

Every response must satisfy the same JSON contract before planning. Screening
covered distance, units, stopping, order, lane ordinals, speed, U-turns,
conditions, negation, ambiguity and attempts to change the parser's role.
Semantic acceptance and strict contract validity are separate, and provider
errors are not counted as misunderstanding.

Timing includes CLI startup and a complete response, excluding map planning.
Screening and repeated tests on the same cases are engineering checks rather
than independent accuracy estimates. Historical model availability was local
to the original setup and is not promised by this repository.

The current adapter, prompt and catalog are in sim/parser; engine/schema.json
is now the single contract. Client configuration and private account details
are excluded from this publication.
